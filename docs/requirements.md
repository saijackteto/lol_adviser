# 要件定義書 — LoL アドバイスプロンプト生成サービス

最終更新: 2026-07-20
ステータス: 確定(ユーザー承認済み)

## 1. サービス概要

League of Legends のチャンピオンセレクト中に、両チームのピック・自分のレーン・ランク帯などを入力すると、レーン戦・集団戦・勝利条件などのアドバイスを LLM に求めるための**プロンプトを生成する** Web サービス。

- 本サービスは **プロンプト生成まで**。LLM API の呼び出しは行わない(ユーザーが ChatGPT / Claude 等に貼り付けて使う)
- バックエンドなしの静的 SPA として構築し、**GitHub Pages で無料公開**する
- 一般公開を前提とする(認証なし・誰でも利用可)
- UI・生成プロンプトともに日本語

## 2. 機能要件

### 2.1 ピック入力(FR-1)

- ブルーサイド / レッドサイド × ロール別(TOP / JG / MID / ADC / SUP)の 10 スロットにチャンピオンを入力する
- チャンピオン選択 UI の必須要件:
  - **インクリメンタル検索**: 「あー」と打ったらアーリが候補に出る。ひらがな入力をカタカナに正規化して照合する。英語名(champion id)でも検索可能にする
  - **アイコングリッド**: 検索結果をアイコン一覧で表示し、クリックで選択
- 同一チャンピオンの重複ピックは不可(選択済みチャンピオンはグリッドでグレーアウト)
- スロットは個別にクリア(選択解除)できる
- **部分入力での生成を許可する**: 全 10 ピック完了前でも「現時点の情報で生成」ボタンでプロンプトを生成できる(チャンセレは 1 ピック約 30 秒しかないため)。未入力スロットはプロンプト内で「不明」と扱う

### 2.2 自分の情報の指定(FR-2)

- **自分のチーム**(ブルー / レッド)と **自分のロール**(TOP / JG / MID / ADC / SUP)を指定する
- 対面(敵レーナー)は「敵チームの同ロールのピック」として自動的に決定する
- **ランク帯** を選択する: アイアン / ブロンズ / シルバー / ゴールド / プラチナ / エメラルド / ダイヤモンド / マスター / グランドマスター / チャレンジャー(未選択も可)
- **サモナースペル**: 自分と対面レーナーのサモナースペル(各 2 つ)を任意入力できる(対面の Flash / Ignite の有無で戦い方が変わるため)
- **BAN 情報**(任意): 両チームの BAN チャンピオンを最大 10 体入力できる

### 2.3 プロンプト生成(FR-3)

生成されるプロンプトは以下の構造を持つ(詳細テンプレートは design.md 参照):

1. **レーン戦** — 自分/相手のパワースパイク、警戒すべきスキルとその CD、トレードの仕方
2. **ガンク警戒** — 敵ジャングラーの初回ガンクタイミング・警戒レベル
3. **集団戦** — 自分の役割、仕掛けるタイミング、敵のキーとなるスキル
4. **勝利条件** — この構成でどう勝つか(スプリット / ポーク / エンゲージ等)、試合時間による有利不利
5. **ビルド・ルーンの対面調整**(任意セクション)

**LLM の知識カットオフ対策(最重要要件)**:

- プロンプトに **現在のパッチバージョンを明記** する(Data Dragon の versions API から取得)
- プロンプトに「あなたの知識が古い可能性がある場合はその旨を述べること」という指示を含める
- **Data Dragon から取得したスキルデータ(スキル名・CD・射程・説明文)をプロンプトに埋め込む**。対象は最低限、自分・対面レーナー・敵ジャングラー。これにより LLM が事実データを参照でき、幻覚が大幅に減る

### 2.4 ワンクリックコピー(FR-4)

- 生成されたプロンプトを 1 クリックでクリップボードにコピーできる(コピー成功のフィードバック表示付き)

### 2.5 テンプレート編集(FR-5)

- プロンプトテンプレートをユーザーが編集できる(質問項目を自分好みに変えたい人向け)
- テンプレートはプレースホルダ変数(`{{selfChampion}}` 等、design.md 参照)を含むテキストとして編集する
- 編集内容は localStorage に保存し、次回訪問時も維持する
- 「デフォルトに戻す」ボタンを設ける

### 2.6 入力履歴(FR-6)

- 生成実行時の入力一式(ピック・ロール・ランク等)を localStorage に保存する(直近 10 件)
- 履歴から選択してワンクリックで入力状態を復元できる

## 3. 非機能要件

| 項目 | 要件 |
|---|---|
| ホスティング | GitHub Pages(無料・静的配信・HTTPS) |
| バックエンド | なし。外部通信は Data Dragon CDN のみ |
| データ鮮度 | アプリ起動時に Data Dragon の最新バージョンを取得し、常に最新パッチのチャンピオンデータを使う |
| パフォーマンス | チャンピオン一覧・アイコンは localStorage / ブラウザキャッシュを活用。初回表示 3 秒以内目標 |
| 対応環境 | モダンブラウザ(PC 優先。チャンセレ中に PC の別ウィンドウで使う想定)。モバイルも崩れない程度に対応 |
| 言語 | 日本語のみ(v1) |
| コスト | 完全無料で運用できること(Data Dragon は認証不要・無料。Riot API キーは使わない) |

### 2.7 広告表示(FR-7・2026-07-20 追加)

- 広告による収益化を行う。ただし**ユーザー体験を損なわない配置に限定**する:
  - ヘッダー直下の横長バナー 1 枠(高さ事前予約でレイアウトシフトなし)
  - 幅 1480px 以上の画面のみ右サイドレール 1 枠(コンテンツ幅 1080px の外側のみ。操作領域に被らない)
  - オーバーレイ / 画面追従 / 全画面 / 音声付き広告は使用しない
- 広告ネットワークは Google AdSense を採用。`src/ads/adsConfig.ts` の client / slot ID が未設定の間は広告関連の DOM・外部スクリプトを一切出力しない
- 前提条件(ユーザー作業): AdSense はサイト登録がドメイン単位のため、github.io のパス配下では実質審査不可。**独自ドメイン取得 + GitHub Pages のカスタムドメイン設定 + AdSense 審査通過**が必要
- Riot ファンプロジェクトポリシー上、広告収益化は許容範囲(Riot IP へのアクセス自体の有料化は不可)

## 4. スコープ外(将来構想)

- **v2**: LLM API 連携によるアドバイス表示の一気通貫(ストリーミング表示)。API キー管理・課金設計が必要になるため v1 では行わない
- **v3**: LCU API 連携によるチャンセレ情報の自動取得。ブラウザからは不可能でローカルアプリ化が必要なため対象外
- 英語等の多言語対応
- ルーン選択 UI(v1 ではプロンプト側で LLM にルーン提案させる)

## 5. 決定事項の経緯(要約)

| 論点 | 決定 |
|---|---|
| プロンプト生成のみ or API 連携 | **A: 生成してコピーするだけ**(ユーザー回答) |
| 自分の情報 | 自レーン・チーム、ランク帯、サモナースペル、BAN(任意)(ユーザー回答) |
| チャンピオンデータ | **Data Dragon**(ユーザー回答) |
| 公開範囲 | 一般公開。GitHub Pages 等の無料手段(ユーザー回答) |
| 技術スタック | 希望なし → **Vite + React + TypeScript** を選定(design.md 参照) |
